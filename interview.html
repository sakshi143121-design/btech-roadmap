Interview prep, step by step

How interviews work, a 4-week plan, common questions with simple answers, and tips for the big day.

How an interview usually works

  • Online test: aptitude, reasoning and coding questions.
  • Technical round: your projects, DSA, and core subjects like OOP and DBMS.
  • HR round: about you, your goals, and whether you fit the team.

Every company is different, and some skip a step, but this order is the most common.

A 4-week plan

  1. Week 1: revise one language and the basics. Solve 10 easy problems.
  2. Week 2: arrays, strings and hashing. Solve 10 more problems and revise OOP.
  3. Week 3: linked lists, stacks, queues and trees. Practice SQL queries.
  4. Week 4: OS and networks, 2 mock interviews, and polish your resume and projects.

Common questions, with simple answers

Tap a group to open it. Learn the idea, then say the answer in your own words.

Programming and DSA
  • Array or linked list? An array has a fixed size and fast access by position. A linked list grows easily and is fast to insert into, but slower to search.
  • Stack or queue? A stack is last in, first out. A queue is first in, first out.
  • What is time complexity? It shows how the running time grows as the input grows. We write it with Big O, like O(n).
  • What is recursion? A function that calls itself on a smaller problem, with a base case that tells it when to stop.
  • What is binary search? It finds an item in a sorted list by cutting the search area in half each time. It takes O(log n).
  • What is a hash map? It stores key and value pairs, and finds a key very fast, on average in O(1).
OOP
  • What is OOP? Organizing code into objects that hold data and actions. Its four pillars are encapsulation, inheritance, polymorphism and abstraction.
  • Class or object? A class is a blueprint. An object is a real item made from that blueprint.
  • What is inheritance? One class gets the features of another class, so you can reuse code.
  • What is polymorphism? The same name behaves in different ways, like overloading and overriding.
  • What is encapsulation? Keeping data and the code that uses it together, and hiding the details with private members.
DBMS and SQL
  • What is a primary key? A column that identifies each row in a table in a unique way.
  • What is a JOIN? It combines rows from two tables using a common column.
  • What is normalization? Organizing tables to reduce repeated data.
  • What is ACID? Atomicity, Consistency, Isolation and Durability. These are the rules that keep a transaction safe.
  • DELETE or TRUNCATE? DELETE removes the rows you choose. TRUNCATE removes all rows at once.
OS and Networks
  • Process or thread? A process is a running program with its own memory. A thread is a smaller part inside a process, and threads share its memory.
  • What is a deadlock? Two or more processes wait for each other, and none of them can move forward.
  • TCP or UDP? TCP is reliable and keeps the order, but it is slower. UDP is fast, but it gives no guarantee.
  • HTTP or HTTPS? HTTPS is HTTP with encryption, so your data is protected.
  • What happens when you type a website address? The browser finds the server's address using DNS, connects to it, sends a request, gets a reply, and shows the page.
HR questions
  • Tell me about yourself. Use this pattern: "I am [name], a [year] B.Tech CSE student. I enjoy [area]. I built [project]. I am looking for [role] to learn and grow."
  • Why should we hire you? Match one skill to the role, and give a project as proof.
  • What is your weakness? Be honest, and explain what you are doing to improve it.
  • Where do you see yourself in 5 years? Say you want to keep learning and grow into a stronger developer.
  • Do you have any questions for us? Always ask one, like about the team, the work, or how you will learn.

On the interview day

  • Think aloud. Interviewers want to hear how you think, not only the final answer.
  • Ask questions first. Make sure you understand the problem before you code.
  • Start simple. Give the easy solution first, then improve it.
  • Test with an example. Run your answer on a small input.
  • Be honest. If you do not know something, say so, and say how you would find out.

Mistakes to avoid: remembering answers word for word, coding in silence, and not being able to explain your own project.
